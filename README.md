## 每月几号重置流量？入方向的流量算不算？

每月 1 日。阿里云在每个自然月的第一天自动重置固定流量配额，重置后重新开始累计。

计费口径只算出网流量，也就是服务器发出去的数据；上传到服务器的入网流量不计费。建站场景下，访客浏览网页、拉取图片产生的都是出网流量，配额基本跟着访问量走。

查用量有两个入口：控制台 → 实例 → 概览 → 服务器监控，能看到流量配额和已用量；订单详情里可以查每月用量明细。发现当月跑得猛，重置日前省着点用，或者提前备好余额就行。

## “200M 峰值带宽不限流量”，实际是什么水平？

先把两个概念分开：带宽是速度上限，单位 Mbps；流量是实际传了多少数据，单位 GB。200M 峰值的含义是瞬时速度最高能到 200Mbps，“不限流量”说的是总量没有配额，两回事。

预期要放平的地方在“峰值”两个字上。这款带宽是共享型峰值带宽，官方标注就是“峰值公网带宽”，不承诺时刻跑满。V2EX 上一个一万三千多人浏览过的讨论帖里，真实用户的反馈大体是这样：

- 短时冲高没问题，下载安装包、应对突发访问能吃到速度红利；
- 长时间持续拉高带宽会被限速。有用户拿来做游戏串流，持续跑高之后被压到 1Mbps 以下；
- 高峰期速度有波动，有人反馈过明显丢包；也有用户表示自己的节点一直没遇到限速；
- 每月几十 GB 量级的正常建站用量，基本感知不到任何限制。

综合下来，这套配置的定位很清楚：给博客、企业官网、小程序后端、低频 API 这类中小流量业务准备的，突发能冲高，总量不设限。如果你的业务要 24 小时持续跑大带宽——视频分发、大文件下载站、实时串流——要么接受被限速的可能，要么这类需求本身就该考虑固定带宽的方案。

另外，“不限流量”的前提是正常使用。服务条款对异常流量和滥用行为照常适用，拿它当免费 CDN 疯狂刷，是有被处理风险的。
